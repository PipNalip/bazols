# Documentation writer

1. Decide the page purpose: tutorial, task recipe, reference, or explanation. Keep one dominant purpose per page.
2. Read the implementation and run every command or verify every path the page claims.
3. Write for the actual reader and lead with their goal.
4. Put exact commands and prerequisites near the step that needs them.
5. Separate durable product behavior from temporary status and open work.
6. Link new high-value docs from the smallest authoritative entry point.
7. Re-check links, paths, examples, and behavior claims before finishing.

Never document planned behavior as already working. Never include secrets, private hosts, personal data, or environment-specific identifiers.
